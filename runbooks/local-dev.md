# Runbook — Local development

Audience: developers getting the stack running on a workstation.

## Prerequisites

- Node 24 + pnpm 10.34.5 (`pnpm.cmd` on Windows PowerShell; do not use Corepack).
- Docker with Compose v2.
- A Supabase project (Auth only for now) with the anon key.

## First-time setup

1. Copy `.env.example` to **two** files:
   - `.env.local` — used by `pnpm dev` / `next build` on the host.
   - `.env` — used by `docker compose` (build args + runtime env).
2. Fill in `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` in both.
3. Set `ATELIER_INTERNAL_SERVICE_TOKEN` to any long random string in `.env`. It is **required**: Compose fails closed without it. Use the same value in `.env.local` when running services on the host.
4. Leave `STRIPE_SECRET_KEY` as a test key or empty for pure-catalog work (see `runbooks/stripe-integration.md`).

## Running the stack

Full stack in Compose (recommended first):

```bash
docker compose up -d
bash scripts/wait-for-healthy.sh
```

Gateway on `http://localhost:3000`; services on `4101`–`4108`.

Hybrid development (host `pnpm dev` + containers for dependencies):

```bash
docker compose up -d postgres message-broker
# then run each service on the host:
pnpm --filter @atelier/account-service dev          # repeat per service
# and the gateway:
pnpm dev
```

Host runs use `*_SERVICE_URL` defaults of `http://localhost:<port>`; Compose runs use Compose DNS names. Do not mix the two URL styles.

## Database

- PostgreSQL is exposed on `localhost:5432` (user `atelier`, dev password `atelier_local_dev` — local dev only, never production).
- Migrations run automatically only on a fresh volume; for an existing volume apply new files manually (see `runbooks/deployment.md` → Migration handling).
- Each service connects with its own least-privilege role (`account_service`, `catalog_discovery_service`, …) restricted to its own schema.
- Backup/restore: `runbooks/backup-restore.md`.

## Validation before pushing

```bash
pnpm validate     # type-check, lint, contract tests, build
```

CI additionally runs the compose smoke test and the Phase 0 boundary grep gates (picsum, token fallbacks, runbook references) — they run locally only inside the compose-smoke context, so keep `pnpm validate` green plus `docker compose config --quiet` with your `.env` present.

## Conventions that fail CI when violated

- No `picsum.photos` (or any remote placeholder generator) in `apps/web-gateway/src`, `services/*/src`, or migrations. Demo imagery lives in `apps/web-gateway/public/img/` (generated by `scripts/generate-placeholder-images.ps1`).
- No `@atelier/*-service` or `@/data` imports in Gateway `src/` (ESLint).
- No working default for `ATELIER_INTERNAL_SERVICE_TOKEN` in compose files.
- Every `runbooks/*.md` referenced by a tracked file must exist.
